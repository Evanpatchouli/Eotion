# 时间轴分组与手序查询性能

用户要求在保证分组结果、筛选与跨页手序正确的前提下，尽量减少大数据量全表扫描；
完成后提交并推送当前主分支全部提交。所有实际数据库验证使用隔离 MongoDB。

## 当前证据

- MongoDB 8.2 隔离库复测：100,000 条记录的稀疏 Select 组首窗约 357 ms，读取约
  100,030 个文档；10,000 条、99% 手排覆盖的一个样本首窗约 642 ms，读取约
  20,154 个文档。样本不是延迟保证。
- MongoDB 8.2 探针验证了 `(workspace,database,token.p,token.v,creationOrdinal,id)`
  复合 multikey 索引：5,000 条中 10 条匹配的 Select 组从检查 5,000 个文档降到
  10 个，特殊属性 ID 和正反向创建序号查询结果与全量 oracle 一致。
- 已有手序实现以 `(slot,rank,recordId)` 合并默认流和 View override 流。不能先截取
  创建序号页再解释手序；也不能把筛选后空批次误判为结束。

## 分组索引

- Record 内仅保存可重建的短字符串属性 token `(propertyId,value)`；不暴露到公共 DTO。
  字符串超过 256 个 Unicode code point 不索引。合法 Select option ID 最多 256 个
  UTF-16 code unit，因此该上限不会漏掉合法选项。对象、数组、null 和未分组不使用此
  索引。所有 Record 创建和属性写入在同一事务中同步 token，残余 `$getField` 判断仍是
  最终真值，特殊字符 ID 按值存储。
- 只有内部就绪版本与实际 Database.version 一致时才使用 token 预筛选。新数据库显式
  标记就绪；标记缺失、过期或重建未完成时继续完整旧查询。旧记录在后台按有界批次从
  当前文档原子重建。扫描前按 Database `_id`、版本和租约原子取得唯一 buildId，并设置
  buildSafeVersion；新版事务仅在该值等于旧版本时随版本推进，旧进程只推进版本会使其
  失配。扫描结束仅在 `_id + buildId` 仍匹配且 buildSafeVersion 等于当前版本时认证；
  一旦失配，必须重新扫描，不能追认。租约由持有者续期，过期后允许接管。新建/更新
  Record 的新版事务同步 token，因此持续的新版本写入不阻止本轮回填。不得以缺省值把旧库误判为就绪。
- 索引和旧版本回填只改善可证明完整的 option 组；未分组、索引未就绪和其他无法证明
  完整的路径保留现有语义。后台失败不能中断读取，也不能伪造空结果。

## 手序默认流

- 优先保留已有的饱和区间证明；对证明不成立的情况，比较按创建序号排序的 Record 索引
  键流和当前 scope override 的来源序号索引键流，跳过覆盖记录，只对真正未覆盖的候选
  批量读取 Record/Page 并执行原筛选。方向、游标边界和远端界均保留同 slot，再按完整
  `(slot,rank,id)` 比较；候选不足时继续读取，直到足额或真实耗尽。
- 索引键的关联依赖现有事务中 Record/override 的一致性；对读取到的错配和孤儿必须明确
  失败，对无法证明的优化前提回退原流，不能静默漏记录。事务内顺序执行读取并保留
  数据库/视图版本围栏。扫描索引键仍可能与数据量成正比，不夸大为全部查询均为常数。

## 验收

真实 Mongo 测试覆盖旧数据回退/回填、并发写入和旧进程失效、特殊 ID/Unicode、无效值、
选项生命周期、256/257 候选分界、显式排序、过滤、跨页同 slot、正反方向、删除/追加、
并发 CAS 和失败回滚；以完整排序 oracle 对照。对 10k/100k 稀疏与密集样本记录
`docsExamined`、`keysExamined`、计划和耗时，性能结论按实际测量报告。运行相关 API、
Domain、HTTP、MCP 与前端回归，独立 review 后提交并推送。
